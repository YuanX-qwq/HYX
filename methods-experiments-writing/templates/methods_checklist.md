# 六要素自查表（方法与实验章节）

逐条打勾；任何一条为否，都必须写进 `limitations` 或 `uncertainty`，不得跳过的同时声称章节完成。

## 1 步骤（steps）
- [ ] ≥2 步，按执行先后编号，编号升序
- [ ] 每步有输入、操作、输出；有条件分支的写明判断条件
- [ ] 没有把多步操作压成一句（"随后训练并评估"不算步骤）

## 2 实验设置（setup）
- [ ] 硬件写明型号（如 GPU 型号与显存）
- [ ] 软件写明版本（python / 框架 / CUDA）
- [ ] 随机种子与重复次数分开写
- [ ] 训练、验证、测试流程分三段描述，条件不串台

## 3 参数（params）
- [ ] 每条参数有名称、取值、单位、作用对象、来源
- [ ] 来源精确到文件（有行号更好）或日志片段
- [ ] 正文出现的每个数值都能在参数表或日志里找到
- [ ] 正文与配置不一致时已标出冲突，未擅自采用任一值

## 4 数据集（dataset）
- [ ] 名称、版本、规模齐全；版本缺失单独标出
- [ ] 划分比例之和为 1（或说明其余部分去向）
- [ ] 预处理步骤写清（增强、归一化、分词等）
- [ ] 各子集用途写清（训练/验证/测试/其他）

## 5 对照实验（baselines）
- [ ] 基线对象与版本写清
- [ ] 是否同预算（同参数量/同训练时长/同算力）写清；不明就写"未说明"
- [ ] 指标与统计方式（单次/均值±标准差/显著性）写清
- [ ] "优于基线"的结论有可比的数值支撑

## 6 可复现与限制（repro / limitations）
- [ ] 代码版本（commit/tag）、环境、种子、命令、数据获取方式齐备
- [ ] 限制指向具体失效场景（换版本/换预算/换数据规模会怎样），不是套话
- [ ] 需作者确认的项已列出，且 `status` 为 `partial`

## 追问清单（材料不足时照此提问）
1. 这个数值来自哪个文件哪一行？没有来源就删除还是保留？
2. 数据集版本号与获取链接是什么？划分用什么随机方式？
3. 基线是否在同一训练预算下跑？重复几次、报告哪种统计？
4. 训练/验证/测试是否真的分离，是否有验证集参与调参？
5. 该步的判断条件是什么（阈值、早停策略、失败回退）？
