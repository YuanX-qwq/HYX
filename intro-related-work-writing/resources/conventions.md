# 通用工作规范（引用自平台 main_template，本题落成可执行规则）

## 1. 读取真实输入
- 原始输入 `/input/case.json` + `task.md`；`case_id` 原样写进 `result.json`。
- 题面与本文件不一致时，以本次 `task.md` 为准。

## 2. 证据与回链
- 每条结论指回：文献键、章节/段落/图表/公式编号、原文短引。
- 区分直接证据（原文句）与推论（由多条共同局限推出）；`evidence_strength` 如实标注 `direct` / `title_only`。
- 读不出、未报告、冲突的内容进 `uncertainty`，不靠猜补。

## 3. 诚实状态
- `success`：五要素齐全、空白有 ≥2 条证据、贡献全部定位成功、无未引用事实句。
- `partial`：完成主体但存在缺口（单一局限、贡献被剔除、存在未引用句），必须在 `uncertainty` 写清。
- `undetermined`：文献库为空或关键材料缺失，无法判断。
- `refused`：要求编造文献/数据，超出范围。

## 4. 产物位置
- 过程放 `/app/work`，最终放 `/app/output`；结构化主结果 `result.json` 必须含全部契约字段。

## 5. 资源与体积（Harbor）
- ≤50 个 UTF-8 文本文件，单文件 ≤500KB，总量 ≤2MB，无符号链接。
- 执行预算 64 请求 / 900 秒 / 每响应 16384 token；尽早保存诚实的部分结果。

## 6. 禁止事项
- 不编造文献条目、DOI、实验数值、测试成绩或运行日志。
- 不写"近年来受到广泛关注""具有重要意义"一类空转句代替具体脉络。
- 不把示例文件当成正式案例结果（示例必须标 `EXAMPLE-CASE-000`）。
