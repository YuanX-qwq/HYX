# 引言与相关工作写作规则

## 1. 三个分组维度（只比较同维度的工作）

| 维度 | 用来回答的问题 | 比较什么 | 不要写什么 |
|---|---|---|---|
| `problem` | 这类任务怎么被定义、用什么数据/场景 | 任务定义粒度、数据覆盖、场景边界 | 不比较模型精度 |
| `method` | 用了哪条技术路线 | 路线差异、适用条件、训练/推理代价 | 不按发表年份罗列 |
| `evaluation` | 怎么衡量、在什么基线之上 | 指标定义、基线选择、实验规模 | 不把指标数值当成结论 |

同一段内不跨维度混写；一条工作若同时涉及两维，只在主维出现一次，另一维写"另见 method 组"。

## 2. 每条工作必须四格齐全

- `conclusion`：该工作**自己**得出的结论（用摘要首句或结果句），不掺入本文评价。
- `conditions`：适用条件（浓度、温度、数据集规模、湿度等），没有原文条件就留空。
- `limitation`：原文承认的局限或与其他工作的冲突，没有原文就留空并降 `evidence_strength`。
- `ref`：文献键，必须能在文献库中查到。

禁用语：`state-of-the-art`（无基线时）、`首次提出`（未核对时）、`广泛认为`（无引用时）。

## 3. 研究空白的三类合法来源

1. **共同局限**：≥2 条已引工作在相同条件下受限（本 Skill 自动聚类，阈值 0.25）。
2. **未覆盖场景**：已引工作的条件字段显示某场景完全缺失（需列出缺什么、为什么重要）。
3. **结论冲突**：两篇工作在同一设定下给出相反结论（需引用双方原句，不替作者裁决）。

写作句式：
- 成立：`现有工作在同一设定下普遍受限于 X（[a]; [b]），本文通过 Y 覆盖该设定。`
- 不成立（单一局限）：`已有工作 a 报告了 X 局限[ a ]；目前仅此一条证据，本文仅将其作为动机而非空白。`
- 无证据：不写空白句，`gap` 留空并在 `uncertainty` 说明缺什么材料。

## 4. 贡献四写法（每条都要定位）

- 方法贡献 → `fig:<图号>`（结构图/流程图）。
- 结果贡献 → `res:<结果编号>` 或 `tab:<表号>`（必须能读到数值）。
- 结论贡献 → `tab:<表号>` 或 `fig:<图号>`（对照实验）。
- 文献贡献 → `ref:<文献键>`（仅用于"我们复现/对比了某工作"这类表述）。

禁止写"显著优于所有基线"除非对照表列出全部基线；禁止把适用范围写成全域（写清数据集与条件）。

## 5. 引用覆盖自查

- 每个含数字或结果动词的句子后面必须有 `[key]`。
- 关键工作（本组代表作）与近 3 年进展必须出现在正文，不只是文献表。
- 引用键必须在文献库中；库里没有的先补条目，不许直接写。
- 同一工作只用一种写法（全称/缩写不混用），题名大小写与库内一致。

## 6. 结构模板（可直接套，但句子要按材料改写）

```
【背景】<年份跨度> 以来，<问题设定> 主要依赖 <数据/任务定义>[key]。
【方法路线】<路线 A> 用 <机制> 处理 <对象>[key]；<路线 B> 进一步 <差异>[key]。
【评价】现有评价以 <指标> 为主，基线包含 <基线列表>[key]。
【空白】上述工作在同一设定下受限于 <共同局限>（[a]; [b]）。
【本文】本文提出 <方法>，在 <数据/条件> 上 <结果数值>（fig:/res:）。
【贡献】1) <方法贡献>（fig:x）；2) <结果贡献>（res:y）。
```
